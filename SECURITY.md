# Security review

This review records repository evidence and its limits. A **source-reviewed** result is not a substitute for testing the release on the Linux host. No production database migration, SMTP relay, or Nginx parser was available in this Windows workspace.

## Findings and controls

| Area | Risk / code path | Fix or current control | Verification |
|---|---|---|---|
| Authentication bypass, hardcoded passwords | Login is in `src/lib/auth.ts`; operational bootstrap is `prisma/seed.ts`. | bcrypt comparison is required; role selection must match the database role. Bootstrap reads protected environment values, hashes passwords, and requires all three operational groups. No fallback password or bypass was found in the reviewed login flow. | Authentication unit tests reject invalid usernames/passwords and cross-role selections. Source review. |
| Sessions and secrets | NextAuth JWT session; `NEXTAUTH_SECRET` is required with no production fallback. | Seven-day session maximum; server checks session user ID and role on protected APIs. SMTP/password values are not sent to client APIs. | Source review. Cookie flags and live session behavior still need deployment verification. |
| Authorization / privilege escalation | Central role map and `requirePermission` protect APIs. | Admin, coordinator, food-admin, and participant permissions are separated. Coordinator export uses `dashboard:view`; food-admin has no export/config permission. | Permission unit tests cover role combinations. Full API route authorization tests are not comprehensive. |
| IDOR / private image access | Participant photo route selects a database image key by participant ID. | Requires `registration:view`; resolves only generated `private://` keys and returns no-store responses. No arbitrary path parameter reaches filesystem APIs. | Source review and traversal validation tests; PostgreSQL-backed access tests were not run. |
| SQL injection | Registration normalized-name lookup uses `$queryRaw`. | User value is a tagged-template parameter. Other business reads/writes use Prisma query objects; no unsafe raw string concatenation was found in reviewed SQL paths. | Source review only. |
| Path traversal / arbitrary file read or write | Filesystem operations are centralized in `src/lib/upload.ts`. | Generated server filenames, logical storage keys, constrained filename regex, and private/public roots. User filenames and paths are not used. | Upload/path validation tests and source review. |
| Upload MIME spoofing / malformed files | Participant image processing accepts JPEG, PNG, WebP. | Declared MIME, signature, strict file boundary, Sharp decode, and 12-million-pixel limit are checked; files are stored privately with restrictive modes. | Unit tests reject fake MIME, malformed/truncated images, GIF participant photos, and traversal keys. |
| Image/request resource exhaustion | Next multipart parsing buffers requests. | Per-photo maximum is exactly 512,000 bytes; API request cap is 2,080,768 bytes for four photos plus overhead. Nginx registration location is 2.1 MiB; global limit remains 9 MiB for payment screenshots. | Exact 512,000 accepted / 512,001 rejected unit test. Config values source-reviewed; Nginx syntax and streaming behavior unverified. |
| Registration abuse / race / duplicates | Public registration endpoint. | Nginx rate limit; backend checks enabled/deadline/capacity; PostgreSQL transaction advisory locks serialize capacity and normalized team-name checks. Team uniqueness has database constraints. | Unit tests cover validation/name rules. Concurrent-capacity integration tests require PostgreSQL and were not run. |
| Team approval/rejection races | Admin status transitions send leader email. | Conditional status updates prevent two concurrent decisions; notifications occur after committed status changes. Successful delivery timestamps are stored. Acknowledgement attempts use a lease and stop after three tries. | Email template/claim tests and source review. Concurrent DB transition tests were not run. |
| SMTP credential exposure / email abuse | `src/lib/email.ts` is the only transport. | SMTP credentials are runtime-only; port 587 requires STARTTLS and 465 uses TLS. Failures return false, log only error class, and do not roll back committed team/status data. Acknowledgements are capped at three delivery attempts. | Tests cover missing config, unavailable SMTP, content, and retry cap. Live relay/credential and mailbox tests unavailable. No secret values are committed in `.env.example`. |
| XSS / unsafe HTML | Dynamic data is rendered in React and HTML email templates. | Interpolated mail HTML values are escaped; targeted search found no `dangerouslySetInnerHTML`. | Template escaping unit tests and source search; full browser XSS testing remains unverified. |
| CSRF / CORS / redirects | No custom CORS middleware or cross-origin API policy is configured. | Authenticated APIs require server-side sessions; NextAuth handles its own auth flow. Login redirects are role-routed in application code. | Source review only. Cross-origin/browser CSRF behavior and reverse-proxy redirect behavior require Linux/browser testing. |
| Security headers / clickjacking / sniffing | `next.config.ts` and Nginx configuration. | App sets `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, Referrer-Policy, Permissions-Policy; Nginx sets HSTS and terminates TLS. | Config source review; `nginx -t` and live response headers were not verified here. |
| Brute force / denial of service | Credential callback and registration endpoints. | Nginx request-rate zones; bounded request sizes; image decode pixel cap; server-side validation. | Configuration review only; load/rate-limit behavior needs target-host tests. |
| CSV injection / corruption | Admin and coordinator exports. | Shared CSV helper quotes cells, prefixes spreadsheet formula-leading data, emits UTF-8 BOM and CRLF. Coordinator CSV is generated server-side from Prisma team/member/payment relations, one row per member, with fixed headers. | Unit tests cover 3/4 member teams, multiple teams, college, degree, IDs, payment, missing values, quotes, commas, and formula strings. PostgreSQL row integration is unavailable. |
| QR / duplicate food check-in | Opaque participant QR token and meal check-in. | Server-generated random QR token; check-in uses participant lookup and database unique `(participantId, mealId)` constraint. | Token and role tests pass. Six database food-check-in tests skip without a PostgreSQL test database. |
| API errors / sensitive logs | Shared `jsonError`, authentication logs, SMTP logs. | Client receives generic 500 details; auth logs do not include submitted credentials; SMTP logs do not include recipients, body, or secrets. Bootstrap logs usernames only. | API error tests and source review. |
| Build/env leakage | Standalone production artifact. | Build performs compilation and artifact preparation only; migrations/bootstrap are explicit commands. Preparation strips `.env*` and upload data. SMTP settings are not `NEXT_PUBLIC_*`. | Build passed; `.next/standalone/.env` absent. Client-bundle secret-value scan cannot be completed without reading protected runtime secrets and was not attempted. |
| Database migration safety | Static CMS tables/config are removed in a forward migration. | Migration renames registration controls, makes limit nullable, removes CMS-only columns/tables, and preserves operational rows/audit history. It is not a database reset. | Prisma schema validation passed. Migration was not applied because this host has no disposable/production PostgreSQL; backup and reviewed Linux application are required. |
| Filesystem permissions / backup | Persistent local storage and systemd unit. | Private directory/file modes are 0700/0600; systemd uses an unprivileged account and restricts writes to `/var/lib/hackmitten`. SETUP documents coordinated DB/storage backup and restore. | Unit/config source review. Fedora ownership, backup encryption, and restore drill remain deployment checks. |

## Outstanding release verification

- Apply the two new migrations on a backed-up disposable PostgreSQL instance, then test registration capacity races, status races, coordinator/admin exports, private image access, and duplicate meal check-in.
- Validate `deploy/nginx-hackmitten.conf` with `nginx -t` and exercise exact body/rate limits on the target Fedora host.
- Exercise systemd permissions, HTTPS/session cookies, SMTP STARTTLS, and backup/restore on that host.
- The application currently buffers multipart bodies through `request.formData()`. The proxy/API limits bound memory use, but streaming multipart parsing is not implemented.
